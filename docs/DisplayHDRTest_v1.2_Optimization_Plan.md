# DisplayHDR Test v1.2 Optimization Plan

## 目標

讓外部自動化測試程式能透過 API 控制所有測試項目及其可變設定，並查詢畫面上實際生效的測試與設定值，以確認切換正確完成。操作不依賴畫面辨識、目前顏色索引或方向鍵次數。既有鍵盤操作保留供人工使用。

## API 用途與後續量測設備整合

導入 DisplayHDR 控制 API 的目的，是讓後續自動化流程串接測試畫面控制與量測設備端 API，實現自動切換測試畫面、核對設定並執行量測。

預期整合流程：

1. 透過 DisplayHDR API 指定測試項目及完整設定。
2. 查詢已生效的測試畫面與設定值，確認對應本次切換指令，並滿足該測試既有的等待條件。
3. 透過量測設備端 API 啟動量測並取得結果。
4. 將量測結果與本次測試識別值、設定快照及狀態版本關聯，再進入下一個測試。

目前優化範圍是提供完整且可核對狀態的 DisplayHDR 控制 API；量測設備端 API 的串接屬於後續整合工作。現階段不將設備廠牌、通訊方式或量測操作寫入 DisplayHDR 測試邏輯。程式回報的 Nits 維持原有計算值，用於核對測試設定；設備量測結果由後續整合流程取得並記錄。

## 核心功能保護原則

- 不改變原有測試項目的測試邏輯、圖樣內容、量測條件、切換流程及既有鍵盤操作；優化以新增 API 控制能力為主。
- 未收到 API 指令時，程式既有操作與顯示行為應維持不變。
- API 指令、錯誤或連線中斷不得造成原有測試流程卡住、當機，或影響人工鍵盤操作。
- API 與既有操作共用狀態時，需確保操作仍在安全的程式執行緒中處理，且不改變既有畫面更新流程。

## 原版狀態（實作前）

- `6` 會進入 `ColorPatches` 測試，但不會重設 `m_currentColor`。
- `ColorPatches` 是 8% 色塊測試；程式另有 `ColorPatchesFull` 全螢幕色塊測試。
- `m_currentColor` 初始為 `0`（Red）；程式執行期間會保留目前索引。
- ↑／↓ 在 RGBW 四色間循環，因此從未知索引出發，固定按幾次方向鍵無法保證到達指定顏色。
- 目前沒有直接選擇 Red、Green、Blue、White 的快捷鍵。
- 目前沒有對外控制 API 或程序間通訊介面；`Main.cpp` 忽略啟動命令列參數。

## 需要修改的項目

1. **盤點並提供共用的測試控制介面**
   - 盤點程式中所有測試項目，以及每個測試可變更的模式、數值與顯示狀態，作為 API 完整度的依據。
   - 在 `Game.h` 宣告可供鍵盤與 API 共用的控制方法或列舉，涵蓋所有測試項目及其可變設定，並提供目前狀態查詢。
   - 在 `Game.cpp` 實作共用控制邏輯；設定值須直接指定，不依賴先前狀態。`ColorPatches`（8% 色塊）與 `ColorPatchesFull`（全螢幕色塊）須能直接設定 RGBW 顏色。
   - 保留既有 ↑／↓ RGBW 循環操作，供人工鍵盤控制。

2. **新增完整的自動化控制與狀態查詢 API**
   - API 必須能控制所有測試項目及其所有可變設定，不限於選擇測試、色塊模式、RGBW 顏色、Nits、字幕狀態或文字顯示狀態等範例。
   - API 必須能一次查詢目前測試項目、使用者可見標題，以及該測試所有設定的實際生效值；欄位應使用明確型別與穩定識別值，讓自動化程式可比較預期值與目前值。
   - 查詢結果須區分設定值為關閉、不適用或尚未生效，不可將不同狀態混為一談。
   - 切換尚未完成時回報未完成；分別回報設定已套用、對應圖樣已提交，以及原有暖機／倒數等待條件，避免將切換完成等同於可立即量測。
   - API 與鍵盤操作共用 Game 的狀態及控制邏輯，避免兩套狀態不同步。

3. **新增本機程序間通訊**
   - 使用 Windows Named Pipe 作為同一台電腦上自動化控制程式與 DisplayHDR 測試程式間的傳輸方式。
   - 不開啟網路服務或對外連線埠。
   - 定義完整控制指令、狀態回覆、錯誤處理與程式關閉時的連線清理方式。
   - 將通訊執行緒收到的控制指令安全地交由程式主執行緒處理，避免從背景執行緒直接操作 Game 或畫面狀態。

4. **保留既有鍵盤操作**
   - 不新增 RGBW 直接選色快捷鍵；自動化測試透過 API 指定顏色並查詢生效值。
   - 不因 API 導入而移除或改變既有測試快捷鍵及 ↑／↓ 顏色循環功能。
   - 不需為尚未新增的快捷鍵修改畫面操作說明。

## 驗收條件

- 未使用 API 時，原有測試項目的測試邏輯、圖樣、量測條件、切換流程及鍵盤操作均維持原狀。
- API 錯誤、連線中斷或無效指令不影響原有測試流程，程式仍可繼續由鍵盤操作。

- 已盤點的每個測試項目及其每個可變設定，均可透過 API 設定並透過查詢讀回。
- 查詢結果包含目前測試項目、使用者可見標題，以及所有適用設定的實際生效值；自動化程式能據此核對預期狀態。
- 不論切換前的程式狀態為何，API 指定測試與設定值後都能直接套用，不依賴鍵盤操作順序。
- API 只在設定套用且對應圖樣完成提交後回報切換完成；原有暖機、倒數與動態測試流程的狀態須另外回報。
- API 對未知指令、無效設定值或不支援狀態回覆明確錯誤，不造成測試狀態錯亂。
- API 控制與既有鍵盤操作保持同步；既有鍵盤快捷鍵及 ↑／↓ 操作仍正常。
- 程式關閉時能清理 Named Pipe 連線與相關執行資源。

## 尚待決定

- Named Pipe 指令與回覆的資料格式及命令名稱。
- 各測試項目的完整設定清單、合法值／範圍及穩定識別值，需依程式盤點結果定義。
- 設定已套用、圖樣已提交及原有量測等待條件的明確判定方式與狀態欄位。
- 無效設定值、不支援設定及切換失敗的錯誤格式。

## 審查後補充要求與設計建議

1. **建立完整控制清單，界定可寫設定與唯讀資訊**
   - 為每個測試列出穩定識別值、原始畫面標題、設定名稱、型別、單位、合法範圍、預設值、適用條件及共用狀態，據此逐項驗收。
   - 完整清單需包含測試等級、棋盤格種類、色塊／黑階／Profile／X-Rite 索引、白階、字幕、說明文字、暫停、自動換色及換色時間等既有操作。
   - 所有可變更的程式設定均須可控制與查詢；倒數、動畫階段、由設定推導的數值及系統／螢幕資訊則依其性質唯讀回報。不得為滿足控制範圍而任意改寫內部資源或系統資訊。

2. **使用明確設定值，並支援一次切換完整測試狀態**
   - 設定介面採用直接指定值，例如字幕關閉、文字隱藏及指定色塊，不以 toggle 或模擬鍵盤次數作為主要控制方式。
   - 支援一次提交測試項目及其相關設定，先驗證全部內容；無效輸入不得造成部分設定已變更。
   - 設定套用順序須配合原有測試初始化。例如 X-Rite 測試的 Update 會在初次切換時關閉自動模式，API 不可在初始化前設定後即宣稱成功。
   - 明確定義切換時未指定設定的保留規則，以及重複設定同一值是否會重新啟動倒數／動畫；維持既有鍵盤切換行為。

3. **以一致狀態快照核對指令與呈現結果**
   - 每次查詢應回傳同一時點的測試、設定及動態狀態，避免混合不同畫格或不同指令的資訊。
   - 建議包含請求識別值、狀態版本與對應畫格識別值，使控制程式可確認查詢對應哪次切換；鍵盤或自動流程造成設定變更時，版本也應反映變更。
   - 快照須依原有初始化、Update 與 Render 流程取得生效值；提交失敗、視窗無法正常呈現或裝置重建期間不得將舊畫格標示為新設定已完成。
   - 說明文字隱藏時，仍須回傳對應測試的原始標題與設定資訊，不能依賴讀取畫面文字。

4. **明確界定軟體查詢能證明的範圍**
   - 分開回報設定已套用、圖樣提交狀態、暖機／倒數剩餘時間及動態測試階段。圖樣提交成功不等同於螢幕物理輸出已穩定。
   - API 的 Nits 應使用原程式相同的換算邏輯，並明確標示為設定／計算值，不能表示成光學量測結果。
   - 查詢包含原始控制值與換算值；保留數值精度，另定義與畫面兩位小數顯示一致的文字格式及比對容差。

5. **制定最小且明確的通訊契約**
   - 建議採用 UTF-8 JSON，定義協定版本、訊息邊界、請求識別值、成功／失敗回覆及錯誤碼。
   - 定義指令逾時後是否仍可能生效，以及控制程式如何重新查詢核對，避免重試造成再次切換或重啟計時。
   - 定義多個程式實例、控制端同時送出指令及鍵盤介入時的處理順序；採主執行緒依序處理並由查詢反映最新狀態。
   - 通訊讀寫、等待控制端與序列化不得阻塞畫面更新；限制指令佇列與訊息大小，避免大量查詢干擾原有測試時序。

6. **以原版建立核心功能驗收基準**
   - 原始碼基準版本為 `68cda1f04eb14dea882dd9309d50f61803413574`；保留原版供同環境比較。
   - 在同一螢幕、HDR／SDR 模式及設定下，比對原版與修改版的靜態圖樣、PQ／色彩換算、HDR metadata、鍵盤操作、切換初始化與動態測試時序。
   - 驗證 API 設定與查詢涵蓋完整清單，包含無效值、切換中的查詢、鍵盤介入、斷線、倒數、自動換色及裝置重建等情境。
   - 比較 API 未連線與持續查詢時的畫面更新／時序影響，依原版基準訂定可接受範圍；無回歸證據前不得宣稱核心功能未受影響。

## 實作狀態（2026-09-30）

- 已新增本機 Named Pipe JSON API，以 `--api` 啟用；未啟用時保留原有操作。
- 支援全部 47 個測試畫面、25 個持續設定的明確指定與查詢，包含 8%／全畫面 RGBW 選擇、字幕、說明文字及原有數值控制。
- 已提供測試標題、適用設定、原始控制值／換算值、請求識別值、狀態版本、畫格、提交狀態、倒數、顯示資訊及 metadata 查詢。
- 先驗證整份請求，再於主執行緒配合原有初始化／Update／Render 套用；原有鍵盤及圖樣函式保留。
- 已提供 Python 標準函式庫客戶端、建置工具與自動化驗證。
- 12 項測試通過；離屏 HDR／SDR 共 320 組畫面及 metadata，比對原版、API 關閉版、API 啟用版一致。
- 實機驗收尚未完成：代理先前自動啟動／診斷執行出現 `DXGI_ERROR_UNSUPPORTED (0x887A0004)`，尚未定位具體失敗呼叫；使用者已確認原版與修改版皆能手動開啟，不能將代理的錯誤概括為使用者環境無法啟動。實際 HDR 輸出、全螢幕切換、裝置重建、效能／動態時序及量測設備整合仍需後續確認。
